# Профили платформ

Профиль — это всё, что зависит от инструмента, играющего роль канонического
wiki. [Контракт формы](../CONTRACT.md) не знает платформы; профиль знает только
её механику и не переопределяет контракт.

Это единственное место в `standards/`, где имя вендора уместно (см.
[tooling axes](../../workspace/tooling-axes.md) — три легитимных места для имени
инструмента). Имя вендора в любом другом файле `standards/` — дефект, а не
деталь.

## Что профиль обязан содержать

1. `PROFILE.md` — механика платформы: чем задаётся заголовок документа, где
   настраиваются шаблоны, чем обеспечивается история ревизий для документов без
   объявленной версии.
2. Тело для каждого из восьми типов §8 контракта — `<Тип>.body.md`. Тело
   содержит таблицу метаданных и заголовки разделов, без содержательного текста.

Профиль, покрывающий не все восемь типов, неполон, и это состояние объявляется,
а не обнаруживается при попытке создать документ.

## Что профиль делать не вправе

Менять порядок полей, отменять двуязычность меток, разрешать оставлять
неприменимые строки пустыми, добавлять самоссылку на канонический адрес.
Расхождение профиля с контрактом — дефект профиля: платформа диктует, *чем*
достигается требование, а не *какое* требование действует.

## Как добавить профиль

Создать каталог `profiles/<платформа>/`, написать `PROFILE.md` и восемь тел,
объявить платформу в `$MERIDIAN_INSTANCE/product.yaml`. Правка стандартов при
этом не требуется — если потребовалась, значит платформенное предположение
просочилось за пределы этого каталога, и чинить надо его, а не профиль.
