# Реестр источников инструкций

Идентификатор реестра: `instruction-source-registry`.

Реестр вводит переносимый контракт **источника инструкций**
(`instruction-source` — зарегистрированный носитель агентских инструкций с
проверяемой идентичностью, областью, расположением, редакцией, дайджестом,
форматом и каналом чтения; [`operating-glossary.md`](operating-glossary.md)).
Контракт описывает, *что* за источник зарегистрирован и *в каком проверяемом
состоянии* он зафиксирован. **Регистрация источника не превращает его
содержимое в принятую норму**: она не даёт тексту полномочий, не принимает
правила и не разрешает конфликты.

Схема — [`instruction-source-registry.schema.json`](../../registries/operating-model/instruction-source-registry.schema.json).
Определения и нормативный смысл — здесь. Проверки согласованности, которые
подмножество JSON Schema выразить не может, выполняет одна общая функция
[`scripts/lib/instruction-source-registry.mjs`](../../scripts/lib/instruction-source-registry.mjs),
которую вызывают и `scripts/kernel-validate.mjs` (участок
`instruction-source-registry`), и самостоятельный набор
`test/instruction-source-registry.test.mjs` — две реализации не расходятся,
потому что реализация одна.

Контракт — **обязательная часть текущего Ядра**. Отсутствие схемы
[`instruction-source-registry.schema.json`](../../registries/operating-model/instruction-source-registry.schema.json)
или продуктово-нейтральных фикстур рядом с ней — ошибка проверки Ядра
(`FAIL`), а не информационный пропуск. Обязательность не переключается через
`VERSION`.

## 1. Граница хранения

Схема, продуктово-нейтральные примеры и проверяемая реализация — Ядро: они
нормы и обязательны. **Данные реестра — Экземпляр** (позже — область рабочих
данных): реестр называет источники конкретного проекта, репозитория или
профиля и в Ядре не живёт. Граница проходит там же, где для реестра приёмки
([`instruction-intake.md`](instruction-intake.md)) и любых других данных и
схем: данные при проекте, правило формы — при инструменте.

Схема не содержит сведений обслуживаемого продукта, абсолютных машинных путей
и зависимости от обязательного отдельного Экземпляра. Зарегистрированный
источник может быть
внешним или просто отсутствовать в текущем чекауте, поэтому проверка
расположения — чистая проверка строки, а не обращение к файловой системе.

## 2. Запись источника — конверт плюс снимок

Каждый источник является записью встроенной модели областей и подчиняется
универсальному конверту записи
([`workspace-scope-model.md`](workspace-scope-model.md) §2): конверт
(`id`, `title`, `record_type`, `scope`, `origin`, `authority`, `payload`)
проверяется существующей
[`scoped-record.schema.json`](../../registries/operating-model/scoped-record.schema.json).
Специализированная схема **не переопределяет конверт**; она добавляет контейнер
`instruction_sources` и контракт снимка источника в `payload` каждой записи.

```yaml
record_type: instruction-source
scope: { type: <одна из шести логических областей>, id: <...> }
origin: { kind: declared | imported | migrated | derived, source_ref: <...> }
authority: { kind: <...>, authority_ref: <...> }
payload:
  normative_status: not-a-norm
  medium: file | external-service
  location: { ... }
  recorded_state: { revision, digest, revision_verified, currency }
  format: <формат содержимого>
  read_channel: { kind, meridian_visibility, agent_auto_read }
  divergence: { status, previous_state?, current_state? }
```

### 2.1. Идентичность (свойство 1)

`id` устойчив, состоит из английских слов в строчном `kebab-case` и уникален в
объявленной области реестра; `title` объясняет источник человеку. В
пользовательском представлении используется форма `Название [идентификатор]`
(принцип `human-agent-readable`,
[`operating-principles.md`](operating-principles.md)). Порядковый номер,
статус, дата, имя актора, средства или модели ИИ в `id` не входят.

### 2.2. Область (свойство 2)

`scope.type` — одна из принятой модели **шести логических областей**
(`built-in-methodology`, `user-profile`, `organization-profile`,
`project-workspace`, `repository-scope`, `run-state`). Область **не выводится
из физического каталога или репозитория**: источник, лежащий в файле
репозитория, может быть в области рабочего пространства проекта, профиля
пользователя или организации. Одинаковое физическое расположение в разных
областях — это разные записи с отдельными происхождением и полномочием, а не
одна запись с неявно расширенной применимостью.

### 2.3. Расположение (свойство 3)

`location` ограничено объявленным носителем `medium`:

- `medium: file` — **обязательны оба поля**:
  - `location.path` — **относительный, уже нормализованный** POSIX-путь внутри
    носителя. Абсолютный путь, ведущий `/`, буква диска, обратная косая черта
    как разделитель и сегменты `.`/`..` отклоняются.
  - `location.container_ref` — **непрозрачная идентичность носителя**
    (репозитория или рабочего пространства). Это идентификатор, а не путь
    файловой системы: абсолютные формы и сегменты `..` отклоняются. Путь без
    носителя не определяет источник — файл `AGENTS.md` существует во множестве
    репозиториев.
- `medium: external-service` — `service_ref` и `resource_ref` (**оба
  обязательны**): непрозрачные идентификаторы службы и ресурса; файлового пути
  нет.

`location.missing_behavior` имеет **единственное допустимое значение** —
`fail-closed`. Скрытого запасного разрешения нет (принцип `no-hidden-fallback`):
неразрешимый источник останавливает работу, а не подставляет родительский
каталог, кэшированную копию или правдоподобный соседний файл. Отсутствие
`missing_behavior` — необъявленное запасное поведение и отклоняется. Значение,
отличное от `fail-closed`, — объявленное скрытое запасное разрешение и тоже
отклоняется.

### 2.4. Редакция, дайджест и актуальность (свойство 4)

`recorded_state` — снимок, который реестр **сейчас держит** для источника:
**явная редакция** (`revision`) и **SHA-256-дайджест** (`digest.algorithm:
sha-256`, `digest.value` — 64 строчных hex-символа). `revision_verified` — был
ли этот снимок сверен с источником.

`currency` описывает отношение снимка к источнику сейчас:

| `currency` | Смысл | Условие |
|---|---|---|
| `current` | снимок сверен и не известно о расхождении | `revision_verified: true` и `divergence.status ∉ { source-missing, source-unreadable }` |
| `stale` | снимок **был** сверен, но более поздняя проверка нашла источник **пропавшим или недоступным** — это последнее известное состояние | `revision_verified: true` и `divergence.status ∈ { source-missing, source-unreadable }` |
| `unverified` | снимок ни разу не сверялся с источником | `revision_verified: false` |

**`stale` имеет одну семантику — только `source-missing`/`source-unreadable`.**
`changed` его не даёт: при `changed` реестр перезаписывает `recorded_state`
свежим наблюдением, и снимок остаётся `current`. Текст и проверка совпадают:
условие в таблице выше и проверка в `scripts/lib/instruction-source-registry.mjs`
допускают ровно `source-missing` и `source-unreadable`.

`current` при `revision_verified: false` запрещён — непроверенная редакция не
объявляется актуальной. `stale` при `revision_verified: false` запрещён:
последний известный **проверенный** исторический снимок объявляется `stale`, а
не подменяется `unverified` (это стёрло бы факт проверки). Проверенный снимок
всегда `current` либо `stale`, никогда `unverified`.

### 2.5. Формат и канал наблюдения источника — раздельно (свойства 5, 6, 8)

`format` описывает **форму содержимого** источника (`agents-md`, `claude-md`,
`cursor-rule`, `kernel-doc`, `markdown-section`, `plain-text`).

`read_channel` описывает **только то, кто и каким способом читает или наблюдает
сам источник**, и моделируется отдельно от формата: ни одно из двух не
выводится из другого. Это **не канал доставки нормы**: ни регистрация
источника, ни его чтение для снятия снимка **не дают его тексту полномочий и не
заменяют `controlled-rule-intake`**, который один разбирает обнаруженный текст
на правила и принимает решение о применении (§3).

`read_channel`:

- `kind`:
  - `agent-native` — инструмент **самого агента** загружает файл (`AGENTS.md`,
    `CLAUDE.md`, правила Cursor), и Meridian в этом пути чтения не участвует;
  - `meridian-observed` — реестр **Meridian сам читает** источник, чтобы снять
    его снимок;
  - `manual` — состояние источника **сообщает человек**.
- `meridian_visibility`: `full`, `partial`, `none` — насколько полно реестр
  Meridian наблюдает источник на его пути к агенту.
- `agent_auto_read`: инструмент агента загружает источник сам, без Meridian в
  пути чтения.

**Автоматическое чтение `AGENTS.md`, `CLAUDE.md` или правил Cursor самим
агентом — отдельное отображение `agent-native` с явной границей видимости
Meridian.** Проверка требует:

- `agent_auto_read: true` ⟹ `kind: agent-native` и `meridian_visibility ≠ full`
  (Meridian не наблюдает полностью файл, который грузит чужой инструмент);
- `kind: agent-native` ⟹ `agent_auto_read: true`;
- `kind: meridian-observed` ⟹ `agent_auto_read: false` (это собственное чтение
  Meridian, а не агента);
- `meridian_visibility: full` ⟹ `kind: meridian-observed`.

### 2.6. Временна́я семантика трёх состояний (свойство 2)

Три состояния относятся ко времени однозначно:

- **`recorded_state`** — снимок, который реестр держит сейчас (§2.4).
- **`divergence.previous_state`** — снимок, который держали **до** последней
  проверки. Историческое состояние; может отличаться от `recorded_state` — в
  этом и смысл расхождения.
- **`divergence.current_state`** — свежее наблюдение источника, которое дала
  последняя проверка.

`recorded_state` и `divergence.current_state` описывают **одно и то же текущее
наблюдение**: когда `current_state` присутствует, его `revision`, `digest.value`
**и признак `verified`** обязаны совпадать с `recorded_state` (`revision`,
`digest.value`, `revision_verified`). Одно наблюдение не бывает одновременно
проверенным и непроверенным. Противоречие по любому из трёх — отказ, в обе
стороны (`revision_verified: true` при `verified: false` и наоборот).
`previous_state` под это правило не подпадает — оно историческое.

`source-missing` и `source-unreadable` **не несут `current_state` вовсе**:
источник, который нельзя наблюдать, не имеет текущего состояния. Если при них
задан `previous_state`, он является последним известным состоянием и **обязан
совпадать с сохранённым `recorded_state`** по `revision` и дайджесту —
расхождение отклоняется.

### 2.7. Состояние расхождения (свойства 7, 10)

`divergence.status` ∈ `{ unknown, unchanged, changed, source-missing,
source-unreadable }`.

`unchanged` и `changed` **вычисляются только по двум проверяемым состояниям**.
Каждое (`previous_state`, `current_state`) несёт `revision`, SHA-256-`digest`
и флаг `verified`. Правило детерминированно и закрыто при неполноте:

- оба состояния присутствуют и `verified: true` — тогда `unchanged` **только
  при совпадении и `revision`, и SHA-256-дайджеста**; различие хотя бы одного
  из них даёт `changed`;
- иначе объявить `unchanged`/`changed` нельзя.

При **двух полных проверенных состояниях** объявленный `status` обязан
совпадать с вычисленным. `unknown` допустим **только** когда доказательств
действительно недостаточно (одно из состояний отсутствует или непроверено); с
двумя полными проверенными состояниями `unknown` отклоняется.

**Изменённый, отсутствующий, недоступный или непроверенный источник не
считается совпадающим.**

## 3. Регистрация и чтение не дают полномочий нормы (свойство 8)

`payload.normative_status` имеет **единственное допустимое значение** —
`not-a-norm`, а `record_type` записи — `instruction-source`, никогда не `norm`.
**Ни регистрация источника, ни его чтение** — ни `agent-native` (агент читает
файл сам), ни `meridian-observed` (Meridian читает источник для снятия снимка),
ни `manual` — **не дают его тексту полномочий нормы**, не принимают правила, не
задают приоритет источников и не разрешают конфликты. `read_channel` описывает
только наблюдение источника, а не доставку нормы. Разбор обнаруженного текста на
правила-кандидаты, классификация, повторы, конфликты и решение владельца —
предмет отдельного пакета `controlled-rule-intake`, который **не обходится**
регистрацией или чтением; приёмка уже существующих норм —
[`instruction-intake.md`](instruction-intake.md). Этот реестр только фиксирует
проверяемый снимок источника.

## 4. Что этот реестр не делает (свойство 14)

- не сканирует файлы проекта и не обходит его дерево;
- не разбирает текст источника на правила;
- не принимает решение о применении и не задаёт приоритет источников;
- не генерирует адаптеры (`AGENTS.md`, `CLAUDE.md`, правила Cursor) и не
  изменяет файлы проекта;
- не мигрирует данные Экземпляра.

## 5. Композиция проверок

Проверка композитна и живёт в одной функции
[`scripts/lib/instruction-source-registry.mjs`](../../scripts/lib/instruction-source-registry.mjs):

1. контейнер и тело `payload` каждой записи — против специализированной
   [`instruction-source-registry.schema.json`](../../registries/operating-model/instruction-source-registry.schema.json);
2. общий конверт каждой записи — против существующей
   [`scoped-record.schema.json`](../../registries/operating-model/scoped-record.schema.json);
3. правила, которые подмножество JSON Schema выразить не может, — кодом
   функции:
   - непрозрачность `container_ref`/`service_ref`/`resource_ref` и относительный
     нормализованный путь; взаимоисключающие формы `location` — `file` требует
     `path` + `container_ref` и запрещает `service_ref` + `resource_ref`,
     `external-service` — наоборот — проверяются схемой (§2.3);
   - связь `currency` с `revision_verified` и с `divergence.status`; `stale`
     только при `source-missing`/`source-unreadable` (§2.4);
   - временна́я согласованность `recorded_state` и `divergence.current_state`
     по `revision`, дайджесту **и признаку `verified`** в обе стороны; для
     `source-missing`/`source-unreadable` — совпадение `previous_state` с
     сохранённым `recorded_state` (§2.6);
   - вычисление расхождения по совпадению **и** `revision`, **и** дайджеста;
     запрет `unknown` при двух полных проверенных состояниях (§2.7);
   - запрет `current_state` при `source-missing`/`source-unreadable`;
   - граница канала `agent-native` — `meridian_visibility ≠ full` (§2.5).

Обе схемы используют поддерживаемое движком подмножество JSON Schema
(`scripts/lib/json-schema.mjs`); неподдерживаемое ключевое слово в любой ветви
делает прогон красным. Схема — Ядро, данные — Экземпляр. **Контракт
обязателен: отсутствие схемы или фикстур в Ядре — ошибка проверки Ядра
(`FAIL`), а не информационный пропуск.** Проверка детерминирована и закрыта
при неоднозначности.

## 6. Изменение контракта

Добавление, удаление или изменение смысла поля — изменение универсальной нормы
Ядра: оно требует записи в журнале изменений и учитывается при выборе следующей
версии. Термин `instruction-source` введён одновременно в
[`operating-glossary.md`](operating-glossary.md) и
`operating-foundation.yaml`; их состав и названия совпадают, и изменение
определения выполняется в обеих половинах сразу.
