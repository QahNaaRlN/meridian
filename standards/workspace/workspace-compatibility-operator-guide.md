# Руководство оператора по совместимости рабочих пространств

Это переносимое, продуктово-нейтральное руководство для человека-оператора,
подключающего уже существующий проект к Meridian и доводящего его до
итоговой квалификации совместимости
([`workspace-compatibility-qualification.md`](workspace-compatibility-qualification.md)).
Оно не заменяет ни один нормативный контракт — только объясняет порядок
шагов и то, какой из пяти составляемых пакетов отвечает за каждый шаг.

Руководство ничего не говорит о конкретном продукте: оно применимо к любому
проекту, подключаемому к любому Экземпляру Meridian.

## Пять шагов

```text
SCAN (сканирование)
  → CLASSIFY (классификация)
  → OWNER DECISION (решение владельца)
  → RESCAN / MIGRATION (повторное сканирование или миграция)
  → QUALIFICATION (квалификация)
```

### 1. Scan — сканирование

Оператор объявляет **ограниченный план обнаружения**
(`payload.discovery_plan`,
[`existing-project-compatibility-mode.md`](existing-project-compatibility-mode.md) §3)
— явный список мест, где могут находиться агентские инструкции проекта
(`AGENTS.md`, `CLAUDE.md`, правила Cursor и подобное). Ядро **не обходит
рекурсивно** дерево проекта: только объявленные слоты плана проверяются.

Для первоначального подключения `scan_kind: initial`. Сканирование ничего не
пишет в подключаемый проект — ни одной операции создания, изменения или
удаления файла нет (§2 того же документа). Каждый найденный источник
становится записью
[`instruction-source-registry.md`](instruction-source-registry.md): проверяемый
снимок расположения, редакции, дайджеста, формата и канала чтения —
**регистрация источника не даёт его тексту полномочий нормы**.

**Результат шага:** запись `workspace-connection-scan` с заполненными
`discovered_sources`/`missing_sources`/`unreadable_sources` — по одному
исходу на каждый объявленный слот плана, без исключения.

### 2. Classify — классификация

Текст, найденный в зарегистрированном источнике, разбирается на **кандидатов
правил** ([`controlled-rule-intake.md`](controlled-rule-intake.md)) —
`payload.rule_candidates[].candidate`. Классификация (`scope`) — явное решение
оператора или детерминированного инструмента разбора, обоснованное
`classification_basis`, а **не** значение, выведенное из физического пути
источника.

Каждый впервые обнаруженный этим сканированием кандидат обязан остаться
`applicability_state: candidate` — обнаружение **не создаёт решение** (§5
того же документа). Повторяющийся кандидат (тот же текст, найденный более
одного раза) объединяется в кластер по явному `semantic_key`, а не по `id`
или порядку чтения.

**Результат шага:** набор кандидатов правил, каждый — `candidate`, с
классификацией и, при повторах, общим `semantic_key`.

### 3. Owner decision — решение владельца

Владелец, чьё полномочие закреплено за областью кандидата (методология,
пользователь, организация, проект или репозиторий —
[`controlled-rule-intake.md`](controlled-rule-intake.md) §9.1), решает по
каждому кандидату: `accepted` (применим) или `not-applicable` (не применим, с
явной причиной). Полномочие запуска (`delegated-run`), которое вело
сканирование или разбор, **никогда** не может само́ принять это решение —
даже при совпадающем `decision_ref`.

Симметрично объявленный конфликт между двумя кластерами (`conflicts_with`)
останавливает принятие обеих сторон одновременно; неоднозначная
классификация внутри одного кластера дублей — тоже. Оба случая требуют
отдельного явного решения владельца, прежде чем продолжать.

**Результат шага:** каждый кандидат либо остаётся `candidate`, либо получает
`accepted`/`not-applicable` с полным `owner_decision`.

### 4. Rescan / Migration — повторное сканирование или миграция

Два независимых продолжения, не обязательно оба сразу:

- **Rescan** (`scan_kind: rescan`) сравнивает новый снимок каждого источника
  с прежним, используя **тот же** механизм расхождения
  ([`instruction-source-registry.md`](instruction-source-registry.md) §2.7).
  Изменение, пропажа или потеря читаемости источника обязаны породить
  соответствующую находку (`findings[]`) — молчаливая перезапись снимка или
  решения не допускается ([`existing-project-compatibility-mode.md`](existing-project-compatibility-mode.md) §7).
- **Migration** составляет план
  ([`instance-data-migration.md`](instance-data-migration.md)), переносящий
  записи переходного Экземпляра в логические области Meridian —
  только для того содержимого, для которого владелец уже принял решение о
  переносе. План обязателен нести обратимость (`payload.rollback`) и
  закреплённый источник с явной ревизией и дайджестом. Когда план минтит хотя
  бы одну `migrated`/`merged` запись, доведение до квалификации требует
  дополнительно составить **канонический экспорт**
  (`instance-data-migration.md` §10) — проверяемое доказательство того, что
  содержимое цели фактически перенесено, а не только заявлено планом.

Рабочее пространство вправе никогда не переходить к миграции и остаться в
режиме совместимости бессрочно — это легальный конечный исход **при условии,
что решение владельца принято по каждому обнаруженному кандидату правила**
(`workspace-compatibility-qualification.md` §4.1, ветвь 5). Кандидат,
оставшийся `candidate`, не позволяет квалификации стать `QUALIFIED` даже
тогда, когда сканирование не сообщает об этом ни одной блокирующей находкой
(§4.1, ветвь 4; §5) — оператор возвращается к шагу 3 для этого конкретного
кандидата.

**Результат шага:** либо новый снимок сканирования с явными находками, либо
составленный план миграции (и, при необходимости, канонический экспорт), либо
и то и другое.

### 5. Qualification — квалификация

Оператор составляет **одну** запись
[`workspace-compatibility-qualification.md`](workspace-compatibility-qualification.md),
несущую закреплённую ссылку на составленное сканирование (обязательно) и, при
наличии, закреплённые ссылки на составленный план миграции и канонический
экспорт — ссылки, а не встроенные копии: обнаруженные источники и кандидаты
правил остаются вне персистентной записи квалификации
(`workspace-compatibility-qualification.md` §1, §5). Квалификация **не
принимает решений заново** — она вычисляет один закрытый вердикт
(`QUALIFIED`/`BLOCKED`/`UNVERIFIED`) из того, что уже составлено и проверено
на предыдущих четырёх шагах, по закрытой матрице решений
(`workspace-compatibility-qualification.md` §4.1).

Три возможных исхода для оператора:

- **`QUALIFIED`** — можно продолжать работу над проектом под Meridian: либо в
  режиме совместимости без миграции, либо с полностью проверенной и
  подтверждённой миграцией.
- **`UNVERIFIED`** — квалификация ещё не завершена: решение владельца ещё не
  принято, доказательство ещё не подтверждено, либо канонический экспорт ещё
  не составлен. Оператор возвращается к шагу 3 или 4.
- **`BLOCKED`** — конфликт, неоднозначность или невоспроизводимый источник
  останавливают квалификацию. Оператор разрешает блокирующую причину (обычно
  возвращаясь к шагу 3) прежде, чем повторить попытку.

## Что оператор никогда не делает вручную

- не пишет и не изменяет файлы подключаемого проекта в рамках сканирования
  ([`existing-project-compatibility-mode.md`](existing-project-compatibility-mode.md) §2);
- не присваивает кандидату полномочие нормы фактом его обнаружения или
  чтения ([`instruction-source-registry.md`](instruction-source-registry.md) §3);
- не выводит решение владельца из порядка, в котором записи оказались
  прочитаны, — только из явно проверяемых полей `owner_decision`/`authority`;
- не заявляет `qualification_state` вручную в обход пересчитываемой матрицы
  решений §4.1 нормативного контракта — заявленное значение, расходящееся с
  вычисленным, отклоняется проверкой Ядра;
- не встраивает составленные записи в саму запись квалификации — только
  закреплённые ссылки, сверяемые внешним резолвером
  (`workspace-compatibility-qualification.md` §1).
